Completed ProjectData Analytics / FinTech

FinTech Transaction & Risk Analytics

Payment performance, customer and merchant behavior, and rule-based flagged activity across 100,000 synthetic transactions.

← Back to Projects

Overview

An end-to-end synthetic FinTech transaction analytics case study covering 100,000 transactions, from Python dataset generation and PostgreSQL analysis to Power BI dashboards and business insights.

Business Problem

Analyze transaction volume and value, payment reliability and failures, customer behavior, merchant performance, geographic patterns, rule-based flagged transaction activity, and risk concentration.

Dataset

Synthetic data for portfolio analysis: 100,000 transactions, 5,000 customers, and 50 merchants, covering January–December 2025.

Analytics Workflow

Python dataset generation → PostgreSQL → data-quality validation → SQL KPI/trend/customer/merchant/risk analysis → risk validation → reporting-ready SQL views → Power BI → DAX → business insights.

Key Results

  • Total Transactions: 100,000
  • Transaction Value: $6.69M
  • Success Rate: 96.03%
  • Failure Rate: 3.98%
  • Flagged Transactions: 4.33%
  • Flagged Transaction Value: $487.34K
  • Customers with Flagged Activity: 10.68%
  • Top 10% of flagged customers generated 30.42% of all flagged transactions
  • International flagged rate: 5.09%
  • Domestic flagged rate: 0.24%

Dashboard

Key Insights

  • Flagged transactions averaged $112.47 versus approximately $64.85 for non-flagged transactions.
  • 534 of 5,000 customers had flagged activity.
  • Germany had the highest flagged transaction rate at 5.14%.
  • Credit Card had the highest payment-method flagged rate at 4.50%.
  • International transactions had substantially higher flagged activity than domestic transactions.
  • Flagged activity was concentrated among a relatively small customer group.

Business Recommendations

  • Prioritize high-risk customer profiles.
  • Apply additional monitoring to international transactions.
  • Prioritize higher-value flagged activity when investigation capacity is limited.
  • Investigate geographic differences before implementing country-specific controls.
  • Monitor payment-method patterns together with other risk indicators.
  • Establish merchant-level monitoring.

Technologies

PostgreSQLSQLPower BIDAXPythonJupyter Notebook

Limitations

This project uses a synthetic dataset for portfolio and analytical purposes. The risk_flag represents rule-based flagged activity and should not be interpreted as confirmed fraud.
